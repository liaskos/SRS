# A: Short Description

A sentence describing the use case informally.
# B: Use Case Details
An instantiation of the entire use case template for the use case. Include: title, actors, preconditions, postconditions, success scenario, any number of alternative flows of events, exception cases, quality requirements, related business rules, assumptions, evidence
(reference to interview transcriptions). 

Do not use tables, use simple markdown headers. 

Use YAML headers for management metadata – more below.

Starter structure below:
## Title
## Actors

## Preconditions

## Postconditions

## Success Scenario

## Alternative Flow 1

## Alternative Flow 2

## Alternative Flow ...

## Exception 1
## Exception 2

## Exception ...

## Quality Requirements

## Frequency of Use

## Assumptions


# C: Diagrams
If applicable, include a System Sequence Diagram (SSD) or an Activity Diagram (whichever is more suitable) to describe the logic of the interaction.

PlantUML is recommended.
# D: Mock-ups

If applicable, include simple drawings of one or more visual user interfaces to show how exactly how the interaction will be supported. 

**LLMS are allowed for generating ideas for you; BUT you have the ultimate accountability.**
